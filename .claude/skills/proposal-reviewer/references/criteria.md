## 1. 평가 축과 점수 기준 (10점 만점)

| 축 | 질문 | 1~3점 | 4~6점 | 7~10점 |
|---|---|---|---|---|
| **독창성** | 기존 서비스와 무엇이 다른가? 그 차이가 가치 있는가? | 기존 서비스의 조합이고, 차별점이 없거나 차별점 자체가 리스크 | 차별점은 있으나 약하거나 근거가 부족 | 분명하고 방어 가능한 차별점이 있고, 경쟁 서비스와 비교 근거가 있음 |
| **실현가능성 (해커톤 MVP)** | 2일 안에 시연 가능한 형태로 만들 수 있는가? | 핵심 기능이 2일 안에 불가능 | 가능하지만 핵심 난제가 범위 밖 | 범위가 명확하고 핵심 난제 일부까지 시연 가능 |
| **실현가능성 (실서비스)** | 경제 구조, 신뢰, 법률·약관 측면에서 실제로 굴러가는가? | 셋 중 하나 이상에서 구조적으로 막힘 | 막히지는 않지만 미해결 과제가 큼 | 주요 과제에 현실적인 해법이 제시됨 |
| **해커톤 적합성** | 심사위원이 이 주제를 채택할 수 있는가? 시연이 설득력 있는가? | 주제나 시연 자체가 감점 사유(약관·법률 리스크 등) | 무난하지만 인상이 약함 | 주최 측 맥락에 맞고, 시연 장면이 핵심 가치를 직접 보여 줌 |

- 점수는 정수로 매기고, 각 점수에 **한 줄 근거**를 붙입니다.
- 이전 리뷰가 있으면 점수 변화와 그 이유를 함께 적습니다.

## 2. 확인 항목

문서마다 아래를 대조합니다. 해당 사항이 없으면 건너뜁니다.

| 항목 | 무엇을 보는가 | 예시 |
|---|---|---|
| **전제의 사실 여부** | 문제 정의와 핵심 가정이 현실과 맞는가 | 구독 상품이 API 키를 주는 것처럼 쓰기, 존재하지 않는 소멸 구조 가정 |
| **경제 구조** | 참여자가 참여할 이유가 성립하는가 | 공급자가 손해를 보는 구조 |
| **약관·법률·규제** | 공급원의 이용 조건, 관련 법규와 충돌하는가 | 제3자 재판매 제한, 가상자산 규제, 콘텐츠 안전 |
| **이름만 바뀐 문제** | 표현은 바뀌었지만 기능이나 주장은 그대로인가 | 탐지 회피 기능을 다른 이름으로 부르기 |
| **문서 간 모순** | 한 문서의 설명이 다른 문서와 어긋나는가 | 한 문서는 Sticky, 다른 문서는 매 턴 교체 |
| **자기모순** | 한 문서 안에서 장점 주장과 한계 인정이 충돌하는가 | 익명성 주장과 신원 서명 요구 |
| **과장 표현** | 근거 없는 절대 표현 | "100%", "완벽", "원천 차단", "세계 최초", "무결점" |
| **출처 없는 수치** | 가격, 크기, 성능, 사용자 수에 근거가 있는가 | 모델 크기, 할인율, 사용자 수 |
| **오래된 정보** | 모델명, 가격, 상품 구성이 현재 기준인가 | 이전 세대 모델명 |
| **검증 불가 주장** | 시스템이 실제로 검증할 수 없는 것을 검증한다고 하는가 | 서명 없는 외부 응답을 자동 판결, 공급자의 모델 바꿔치기 |
| **시연 가능성** | 시연 장면이 2일 안에 실제로 가능하고, 시연 자체에 리스크가 없는가 | 약관 위반 장면을 시연, 생성에 수 분 걸리는 작업을 라이브 시연 |
| **용어 정의** | 핵심 용어가 정의되고 일관되게 쓰이는가 | 토큰, 포인트, 크레딧의 혼용 |

## 3. 사실 확인 규칙

- 가격, 약관, 상품 사양, 크레딧 정책, 경쟁 서비스 현황은 **바뀔 수 있는 사실**입니다. 웹에서 확인하고, 보고서 끝에 출처 링크를 남깁니다.
- 1차 출처(공식 문서, 약관, 가격표)를 우선합니다. 제3자 집계 사이트끼리 값이 다르면 그 사실을 적고 단정하지 않습니다.
- 확인하지 못한 사실은 **"미확인"**으로 표시합니다. 그럴듯한 값을 지어내면 사용자가 그 값을 문서에 옮겨 적게 되어 피해가 커집니다.
- 법률 판단은 "위험 소지"와 근거 조항까지만 씁니다. 최종 판단은 법무 확인이 필요하다고 덧붙입니다.

## 4. 심각도

| 심각도 | 기준 |
|---|---|
| **치명** | 심사에서 바로 탈락하거나, 실서비스에서 구조적으로 성립하지 않음 |
| **높음** | 심사위원이 반드시 질문할 약점. 답이 준비되지 않으면 큰 감점 |
| **중간** | 신뢰도를 떨어뜨리는 오류, 모순, 과장 |
| **낮음** | 표현, 용어, 형식. 보고서에만 기록하고 체크리스트에는 넣지 않음 |

## 5. ID 체계

`review/review-checklist.md`와 같은 체계를 씁니다.

| 영역 번호 | 영역 |
|---|---|
| R1 | 핵심 전제 |
| R2 | 법률·약관 |
| R3 | 기술적 주장의 오류와 자기모순 |
| R4 | 독창성 |
| R5 | 해커톤 적합성 |
| R6 | 권고 사항 |

새 지적은 해당 영역의 마지막 번호 다음 번호를 씁니다(예: R3-7 다음은 R3-8).
