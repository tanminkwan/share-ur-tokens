## 0. 이 단계의 의미

고급 검색 peer는 **기간계 시스템의 엔드포인트가 peer가 되거나, 하나의 peer가 그 서비스를 중계하는 모델**의 첫 실증이다(사용자 2026-10-30). 검색 peer는 bge-m3 서비스를 고치지 않고 감싸서 A2A op로 내놓는다. 묻는 쪽 확인, 닫힌 그룹, 응모 대상 규칙은 peer가 지킨다. 자세한 틀은 [design.md](design.md) 0절에 있다.

## 2. 고급 검색 peer: 실제 bge-m3

### 말은 다르고 뜻이 같은 질의 (일반적인 경우)

질의: "새로 입사한 동료의 적응을 도와줄 사람"

| 문서 | BM25 | bge-m3 코사인 |
|---|---|---|
| **신입 사원 온보딩 프로그램을 운영해 왔다** (정답) | 0.0 | **0.789 (1위)** |
| 행사 예산과 공간을 잡는 총무 담당 | 0.0 | 0.712 |
| 서버 장애 복구와 운영 자동화 담당 | 0.0 | 0.699 |
| 고객 제안과 수주 협상 | 0.0 | 0.656 |

BM25는 겹치는 단어가 없어 아무것도 못 찾았고, bge-m3는 정답을 1위로 올렸다.

### 확인된 한계: 질의의 단어로 만든 방해 문장

질의: "새로 입사한 동료가 회사에 빨리 녹아들게 돕는 사람"

| 문서 | BM25 | bge-m3 코사인 |
|---|---|---|
| 회사 서버 장애가 나면 빨리 복구하는 사람 | 6.251 (1위) | 0.770 (1위) |
| **신입 사원 온보딩 프로그램을 운영해 왔다** (정답) | 0.0 | 0.767 (2위) |
| 회사 행사 예산과 공간을 빨리 잡아 주는 총무 담당 | 2.734 | 0.766 |
| 고객 제안과 수주 협상 | 0.0 | 0.638 |

방해 문장이 질의의 단어(회사, 빨리, 사람)를 거의 다 갖고 있으면, bge-m3만으로는 정답이 0.003 차이로 2위다. BM25는 정답에 0점을 준다. 이 한계는 테스트로 남겨 두었다(정답이 상위 2위 안인지 검사). 보완은 재정렬 모델(bge-reranker-v2-m3)로 하며 범위 밖으로 남긴다.

### 검색 peer 프로세스 (A2A)

broker 프로세스 하나에 프로필 4개와 공지 2개를 올리고 `python -m arena.peers.search`를 띄웠다.

| 확인 | 결과 |
|---|---|
| 첫 색인 | 프로필 5개(검색 peer 자신 포함), 공지 2개, 차원 1024 |
| 프로필 질의 (위 질의) | 정답 1위 0.7317 |
| 공지 질의 "신입 사원 온보딩" (서명 요청) | "새로 온 동료의 첫 달 적응을 돕는 방법 모집"이 1위 0.712, "서버 비용 절감"은 0.5535 |
| 발견 | 다른 peer가 broker에서 역할 `search`로 검색 peer를 찾음 |

**발견하고 고친 것**: 처음에는 검색 peer 자신의 프로필이 사람 검색 결과 2위에 섞였다. 검색 peer는 broker에서 역할로 찾으므로 자기 프로필을 결과에서 빼도록 고쳤다(P3-B3 문구에 반영).

실행 기록은 [evidence/live-search-bge-m3.txt](evidence/live-search-bge-m3.txt)에 있다.

## 3. 관전용 절대자 peer

broker 프로세스, recorder 프로세스(열람 허용 목록에 절대자 키), `python -m arena.peers.overseer`를 띄우고, 열람자 키로 A2A `overseer_snapshot`을 불렀다.

| 확인 | 결과 |
|---|---|
| 기록자 찾기 | broker 역할 검색(`record`) → 검색 결과의 recorder 주소 |
| 감사 | 사본을 스스로 감사, 정상. 단위 테스트에서 과거 항목을 고치면 `TAMPERED at seq 3`, 경고 로그 한 번 |
| 통계 | 항목·종류·서명자·이벤트(결재자 포함)·판정별 수와 숫자 항목 평균·역할별 계약·공유 흐름. 판정·역할 이름은 문자열로만 다룸 |
| peer별 | 프로필 요약(강점)과 원장 기여를 공개키로 묶음. 프로필이 없는 결재자도 원장에 있으면 나옴 |
| 열람 제한 | 열람자가 아닌 키의 요청 거부, 서명 없는 요청 거부 |

## 4. 2단계 실제 LLM 테스트의 불안정과 조치

이번 전체 실행 중 한 번, 2단계의 경연 모티브 실제 LLM 테스트가 실패했다. 심사자 역할을 맡은 LLM이 "역할을 맡을까요?"라는 질문을 "지금 평가하라"로 읽고 거절했다. 원인은 테스트 대역의 질문 문구였다. 질문을 "지금 평가하라는 것이 아니라 나중에 이 역할을 맡을지 정하는 것"으로 분명히 했다. 이유를 한 문장으로 쓰라는 지시도 더했다. 그 뒤 세 번 연속 통과했고, 결재·수락 이유도 판단 근거를 담은 문장으로 나왔다. 실행 기록: [../phase2/evidence/live-motif-gpt-oss-120b-run2.txt](../phase2/evidence/live-motif-gpt-oss-120b-run2.txt).

## 5. 남은 한계

- 벡터 색인은 메모리에만 있다. 재시작하면 첫 갱신 때 모두 다시 임베딩한다.
- 색인 갱신은 주기 방식이다(broker 변경 알림 없음).
- 재정렬과 BM25 섞기는 하지 않았다.
- 닫힌 그룹 회원 확인은 "그 그룹 색인에 묻는 peer의 프로필이 있는가"로 한다. 허가가 만료돼도 프로필이 broker에서 내려가기 전까지는 회원으로 본다.
