# 5단계 요구사항: 검증과 플랫폼 완성

> 상태 표기: ⬜ 미착수 · 🟡 진행 · ✅ 테스트 통과. 번호는 테스트 이름과 맞춘다(P5-A1 → `test_p5a1_...`).

## 0. 목표

이 단계를 통과하면 **플랫폼 완성**이다. 세 부분으로 나눈다.

1. **5-A 인수에 필요한 범용 기능**: 이벤트 종료, 공동 확인(여러 당사자 서명), 역량 분야 표준 목록.
2. **5-B 검증**: 변조와 권한 없는 열람을 한곳에 모아 점검하고, 실제 LLM 흐름을 반복해 안정성을 잰다.
3. **5-C 인수 확인**: peer 간 가위바위보 이벤트([../acceptance-rps.md](../acceptance-rps.md))를 메모리 세계와 실제 프로세스·실제 LLM으로 돈다.

## 5-A. 범용 기능

| 번호 | 요구사항 | 상태 |
|---|---|---|
| P5-A1 | **이벤트 종료**(`close`): 발행자가 서명하는 원장 항목. 결과 해시(`result_hash`)를 담을 수 있다. 선언된 이벤트만, 발행자만, 한 번만 닫는다 | ⬜ |
| P5-A2 | 종료된 이벤트를 가리키는 계약·먼저 등록·판정·공동 확인은 거절한다("event closed") | ⬜ |
| P5-A3 | **공동 확인**(`attest`): 종류(`kind`), 대상(`subject`), 값(`value`), 당사자 목록(`parties`), nonce를 담고, 당사자 **전원**이 서명해야 기록된다. 당사자는 한 명 이상이고 겹치지 않는다 | ⬜ |
| P5-A4 | 같은 이벤트 안에서 같은 (종류, 대상)은 한 번만 공동 확인된다. nonce는 한 번만 쓴다 | ⬜ |
| P5-A5 | 이벤트 policy에 `attest_roles`(종류 → 역할 또는 `issuer`)를 둘 수 있다. 정해진 종류는 당사자 전원이 그 역할의 계약자여야 한다(`issuer`면 당사자가 발행자 한 명). 정하지 않은 종류는 자유 | ⬜ |
| P5-A6 | 기여 집계에 공동 확인 종류별 참여 수(`attested`)와 닫은 이벤트 수(`closed`)를 더한다. 통계에 닫힌 이벤트와 공동 확인 종류별 수를 더한다 | ⬜ |
| P5-A7 | recorder 공개 확인은 종료면 이벤트·발행자·결과 해시, 공동 확인이면 종류·대상·당사자·값, 먼저 등록이면 작성자·내용 해시를 준다(내용은 원장에 없으므로 해시까지만) | ⬜ |
| P5-A8 | **역량 분야 표준 목록**(`ARENA_LABEL_FIELD_VOCAB`, 쉼표 목록): 비어 있지 않으면 분야 라벨은 목록 안의 이름만 붙는다(LLM에 목록을 주고, 목록 밖 이름은 버림). 비어 있으면 자유롭게 짓는다(4단계 동작) | ⬜ |

### broker 그룹 식별자 (사용자 2026-10-30: 어떤 그룹에서 일어난 일인지 추적)

| 번호 | 요구사항 | 상태 |
|---|---|---|
| P5-A9 | broker는 그룹 식별자(`ARENA_BROKER_GROUP_ID`)를 가진다. 같은 그룹의 broker는 같은 식별자를 쓴다. `GET /health`, 프로필 목록·검색 결과에 `group_id`가 실린다 | ⬜ |
| P5-A10 | 공지는 발행자가 서명한 `group_id`를 담아야 하고, broker는 자기 그룹과 다른 공지를 받지 않는다(이웃이 전달한 공지도 같음) | ⬜ |
| P5-A11 | **원장의 모든 항목**은 페이로드에 `group_id`(빈 값 아님)를 담는다. 없으면 기록자가 거절한다. 당사자가 함께 서명하므로 나중에 바꿀 수 없다 | ⬜ |
| P5-A14 | **그룹 생성 공증**(사용자 2026-10-30): broker 그룹을 처음 만드는 peer가 **그룹 선언**(`group`) 항목을 남긴다. 만든 peer가 서명하고 `group_id`, 만든 peer(`founder`), 닫힌 그룹 여부(`closed`), 소속 broker 공개키 목록(`brokers`)을 담는다. 같은 `group_id`는 한 번만 선언된다 | ⬜ |
| P5-A15 | 그룹 선언을 요구하는 설정(`ARENA_RECORDER_REQUIRE_GROUP`, 기본 켬)이 켜져 있으면, 그룹 선언 밖의 모든 항목은 **이미 선언된 그룹**의 `group_id`만 쓸 수 있다(아니면 "unknown group"). 그래서 모든 기록이 그룹을 만든 peer까지 이어진다 | ⬜ |
| P5-A17 | **만민 그룹**(사용자 2026-10-30: 태초부터 존재하는 만민을 위한 broker 그룹): 제네시스가 만드는 열린 그룹(`ARENA_GENESIS_GROUP_ID`, 기본 `public`). 그룹 선언으로 만들 수 없고(이미 있음), 닫힌 그룹이 될 수 없다(소유자 설정 시 시작 오류). 그룹 식별자를 정하지 않은 broker는 만민 그룹이다 | ⬜ |
| P5-A18 | **제네시스**(사용자 2026-10-30: god이 broker와 recorder를 만들면서 생태계가 시작되고, 그 최초의 행위를 제네시스라 부른다): god peer가 만민 그룹 broker와 기록자를 만들고, 원장의 **0번 항목으로 제네시스**(`genesis`)를 남긴다. god이 서명하고 만민 그룹 식별자, god, broker, recorder의 공개키를 담는다. 제네시스는 원장 맨 앞에 한 번만 온다. 그룹 선언 요구가 켜져 있으면 원장은 제네시스로 시작해야 하고, 만민 그룹은 제네시스 뒤부터 선언 없이 쓰인다. god의 키는 처음부터 그 기록자의 열람 허용 목록에 있다. `python -m arena.genesis`가 이 행위를 하고, 키와 원장은 파일에 남아 다시 띄우면 같은 생태계로 이어진다(저장된 제네시스와 키가 다르면 시작 거부) | ⬜ |
| P5-A16 | 공개 확인은 그룹 선언이면 `group_id`, `founder`, `closed`, `brokers`를 준다. 기여 집계에 만든 그룹 수(`groups`), 관전 통계에 선언된 그룹 목록을 더한다 | ⬜ |
| P5-A12 | 공개 확인 응답에 `group_id`, 관전 통계에 그룹별 항목 수가 실린다 | ⬜ |
| P5-A13 | peer는 broker 그룹의 식별자를 `group_id(그룹 이름)`로 얻는다(broker에 물어 기억) | ⬜ |

## 5-B. 검증

| 번호 | 요구사항 | 상태 |
|---|---|---|
| P5-B1 | **변조 점검표**: 과거 항목의 내용·참여자 서명·기록자 서명 변경, 항목 끼워 넣기, 순서 바꾸기, 가운데 항목 삭제를 감사가 모두 찾는다 | ⬜ |
| P5-B2 | **끝 잘라내기**는 감사만으로는 못 찾는다(체인이 여전히 맞음). 참여자가 보관한 기록자 서명 영수증과 대조하면 찾는다(`Receipts.missing_from(chain)`) | ⬜ |
| P5-B3 | **권한 없는 열람 점검표**: recorder 전체 열람(허용 목록 밖, 서명 없음, 다른 경로 서명, 시각 폭 밖의 다시 보내기), 접근 기록 열람, 닫힌 broker 그룹 검색, 관전 결과 열람이 모두 거부되고, recorder 접근 기록에 남는다 | ⬜ |
| P5-B4 | **반복 안정성**: 실제 LLM 경연 모티브 흐름을 5회, 실제 LLM 가위바위보 인수 흐름을 3회 연속 돌려 통과 횟수, 소요 시간, LLM 대체값 사용 횟수를 잰다 | ⬜ |
| P5-B5 | 실행 기록을 `dev/phase5/evidence/`에 보관한다 | ⬜ |

## 5-C. 인수 확인: 가위바위보

[../acceptance-rps.md](../acceptance-rps.md)의 통과 조건 RPS-1 ~ RPS-7을 그대로 요구사항으로 삼는다.

| 번호 | 요구사항 | 상태 |
|---|---|---|
| P5-C1 | RPS-1 참가: 공지로 모으고, 가상의 사람(소유자)이 참가를 정한 peer만 `player` 계약 | ⬜ |
| P5-C2 | RPS-2 경기는 두 선수 사이 A2A로만(개최 peer·broker를 거친 경기 메시지 0건) | ⬜ |
| P5-C3 | RPS-3 공개 전 해시 등록, 공개된 수와 해시 일치. 어긋나면 몰수 | ⬜ |
| P5-C4 | RPS-4 경기 결과는 두 선수 공동 확인. 한쪽만 서명하면 거절 | ⬜ |
| P5-C5 | RPS-5 개최 peer의 순위 공증 = god peer가 원장만으로 다시 계산한 순위 | ⬜ |
| P5-C6 | RPS-6 종료 기록 뒤 이 이벤트 항목 거절, broker 공지 마감 | ⬜ |
| P5-C7 | RPS-7 실제 프로세스로 돌고, 수 고르기를 실제 LLM으로 한 번 이상 | ⬜ |
| P5-C8 | 결과를 `dev/phase5/test-results.md`에 적고, 플랫폼 완성 여부를 판정한다 | ⬜ |
