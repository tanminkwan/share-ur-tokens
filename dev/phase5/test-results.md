# 5단계 테스트 결과 (진행 중, 2026-10-31 멈춤)

> 이 문서는 아직 완료 판정이 아니다. 사용자 지시(2026-10-31 "오늘은 그만해, 상태를 정확하게 기재해")로 실제 실행 12 도중에 멈추고, 그 시점의 상태를 적는다.

## 1. 한 줄 요약

- 실제 LLM을 쓰지 않는 테스트: **254개 모두 통과**(`pytest --ignore=tests/live`).
- 앱 없는 가위바위보 인수(실제 LLM, `tests/live/test_rps_acceptance.py`): **13번 실행 중 통과 1번(실행 7)**. 실행 13은 플랫폼 흐름을 221초 만에 끝까지 돌았지만 불완전한 공개값 묶음 때문에 실패로 판정됐다(2026-11-02). 실행 12는 세 경기를 4분 안에 모두 끝냈지만, 개최자가 순위 공증을 미룬 채 기다리는 중에 사용자 지시로 멈췄다.
- 이 실행들의 목적은 통과 자체가 아니라 **플랫폼이 갖춰야 할 기본 기능을 찾아 넣는 것**이다(사용자 2026-10-30). 실행마다 드러난 문제를 범용 기능으로 넣었다(P5-C23 ~ C42).
- **플랫폼 완성 판정: 아직 아님.** 인수 통과의 반복 성공률을 재지 못했다.

## 2. 판정 기준 (사용자 2026-10-31)

- **플랫폼 실패로 세는 것**: 제시간에 이벤트가 닫히지 않음, 원장 검증 실패(서명, 규칙 해시, 공개값과 등록 해시, 배정), 공증된 순위가 원장의 공동 확인 결과로 다시 계산한 순위와 다름.
- **따로 기록하고 실패로 세지 않는 것**: 승패를 거꾸로 판정하는 것 같은 **LLM 판정 오류**. 사용자: "llm 품질 문제이면 됐어. 중요한 것은 이런 부분 때문에 code를 사용한 app이 등장하는 거지." 게임의 의미(승패 계산)는 플랫폼에 넣지 않는다.
- 몰수패는 따로 센다(실행 7의 몰수는 정직한 선수가 공개값을 손으로 옮기다 틀린 것이었다).

## 5. 다시 시작하는 방법

```bash
.venv/bin/python -m pytest -q --ignore=tests/live          # 254개, 약 15초
rm -rf data/runs/runN-tmp && timeout 1900 .venv/bin/python -m pytest tests/live/test_rps_acceptance.py -q -s \
    -p no:cacheprovider --basetemp=data/runs/runN-tmp > data/runs/rps-runN.log 2>&1   # 실제 LLM, 최대 25분
```

- 실제 실행에는 `.env`의 Samsung SDS Cloud AI 서비스 키와 bge-m3 임베딩 서비스(`localhost:8000`)가 필요하다.
- `--basetemp`를 주어야 원장 파일(`data/runs/runN-tmp/.../genesis/ledger.jsonl`)이 남는다. 실행 7의 원장은 이것 없이 돌려 사라졌다.
- 각 peer의 이벤트 상태와 대화 기록은 `data/events/<공개키 앞 16자>/assistant/events/<event_id>/state.json`에 남는다.
