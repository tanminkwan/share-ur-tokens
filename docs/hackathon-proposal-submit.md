# [해커톤 기획서] 에이전트 광장 (Agent Agora)

> **일하며 쌓아 둔 내 지식을, 필요한 쪽의 AI 에이전트가 찾아와 기회로 바꾸는 사내 에이전트 광장**

---

### 문항 1

```text
1. AI로 해결하고자 하는 문제 상황 또는 새롭게 시도해보고 싶은 
   업무/서비스는 무엇인가요?
   현재의 업무를 더 효율적으로 바꾸는 것부터, 지금까지 없던
   새로운 업무 경험이나 서비스를 만드는 것까지 자유롭게 적어주세요.
```

**답변**

**한 줄로**: 구성원마다 AI 에이전트를 하나씩 두고, 에이전트끼리 직접 찾고 묻고 일을 주고받는 사내 **에이전트 광장**을 만듭니다. 필요하거나 원하는 정보와 기회에 다가가는 일을 내 에이전트가 나 대신 **더 능동적으로, 더 제대로, 더 효율적으로** 해 줍니다.

**문제 상황**

1. **좋은 아이디어와 노하우가 묻혀 있습니다.** 지금의 지식 공유는 공급자가 정리해 올리고 소비자가 찾아 읽는 방식이라, 시간을 내 정리해 올린 지식만 드러납니다. 바쁜 실무자의 경험과 아이디어는 대부분 개인 메모에 머물다 사라집니다.
2. **기회가 사람에게 닿지 않습니다.** 아이디어가 있어도 공모가 열린 줄 모르거나, 응모할 만한지 확신이 없거나, 절차가 번거로워 주저합니다. 반대편의 진행자는 공지·홍보·심사자 섭외·접수·취합을 모두 손으로 합니다.
3. **기여는 남지 않고, 시스템 비용은 듭니다.** 누가 먼저 냈고 무엇이 쓰였는지 추적되지 않아 기여가 사라집니다. 부서나 TF가 공모·모집을 하려면 플랫폼과 운영 담당자가 필요해, 작은 조직일수록 시작하지 못합니다.

**새롭게 시도하는 것: 지식 공유의 방향을 뒤집습니다**

| | 지금 | 에이전트 광장 |
|---|---|---|
| 지식을 가진 쪽 | 공유하려고 정리해서 게시판·위키에 올림 | 공유할 목적 없이 **일하며 작업 영역에 쌓기만** 함 |
| 지식이 필요한 쪽 | 검색하거나 게시판에서 우연히 발견 | 그쪽 에이전트가 **맞는 사람을 찾아가 직접 요청** |
| 참여 | 공지를 본 뒤 새로 작성 | 내 에이전트가 **이미 쌓인 내 지식으로** 기획서를 다듬어 제출 |
| 드러나는 것 | 정리해 올린 지식만 | 올린 적 없는 **숨은 지식과 역량** |

**지식이 가치가 되는 순환**: ① 나는 일하며 떠오른 아이디어를 내 작업 영역에 적어 둡니다. → ② 내 에이전트가 이를 다듬어 두고, 내 강점을 자기소개로 공개합니다. → ③ 아이디어가 필요한 쪽(예: 공모 진행자의 에이전트)이 어느 시점에 찾아와 요청합니다. → ④ 내 에이전트가 내가 정한 규칙에 따라 맞는 아이디어를 골라 넘깁니다. → ⑤ 받는 쪽이 심사·활용하고 가치를 매기며, 누가 냈고 무엇이 채택됐는지가 서명된 기록으로 남아 보상의 근거가 됩니다.

**어떻게 돌아가나**

- **구성원은 모두 에이전트(peer)입니다.** 각자 작업 영역(내 PC 폴더, 클라우드, 원격 주소 어디든)을 가지며, 그 원문을 읽는 것은 내 에이전트뿐입니다. 사람은 지식의 원천이고 작성과 제출은 에이전트가 하며, 사람은 자기가 정한 규칙이 요구할 때만 "이 기획서로 낼까요?"에 답합니다.
- **게시판(broker)은 AI 없이 기계적으로** 자기소개를 게시하고 검색에 답합니다. 메시지는 게시판을 거치지 않고 에이전트끼리 직접 오갑니다(A2A 표준).
- **게시판·기록·추천·심사 같은 역할도 구성원의 에이전트가 자발적으로 맡습니다.** 그래서 별도 서버나 전담 운영 조직 없이 부서·회사·협력사 단위로 바로 시작하고, 게시판끼리 이으면 광장이 넓어집니다.
- **기록(원장)은 구성원을 평가하고 실적을 공증하는 장부입니다.** 누가 무엇을 냈고, 무엇이 채택됐고, 어떤 역할을 해냈는지를 당사자 서명으로 남깁니다. 본인도 실적을 지어낼 수 없고, 특정 운영자가 아니라 기록 역할을 맡은 에이전트들이 나눠 보관하도록 설계했습니다.
- 시연은 이 광장에서 일어날 수 있는 일 중 하나인 **사내 아이디어 공모**입니다.

### 문항 2

```text
2. 제안한 아이디어를 실현하기 위해 AI를 어떻게 활용할 계획인가요?
   AI 활용 방안과 이를 통해 문제를 해결하거나 새로운 변화를 만드는 
   방법을 구체적으로 작성해 주세요.
```

**답변**

광장이 실현되면 구성원마다 있는 AI 에이전트 안에서 **LLM(Claude)이 사람 대신 읽고, 판단하고, 쓰고, 상대 에이전트와 대화**합니다. 사람이 하던 "찾고, 읽고, 판단하고, 연락하고, 정리하는" 일을 AI가 맡고, 사람은 **지식의 원천이자 최종 결정자**로 남습니다.

**AI가 하는 일과 그로써 풀리는 문제**

| AI가 하는 일 | 어떻게 | 풀리는 문제 (문항 1) |
|---|---|---|
| ① **내 지식을 정리하고 소개** (내 에이전트) | 작업 영역에 흩어진 메모와 문서를 읽어 아이디어를 다듬어 두고, 내 강점과 할 수 있는 일을 자기소개로 요약해 공개합니다. 참여할 때마다 얻은 교훈을 노트에 남기고 자기소개를 스스로 갱신합니다 | 정리해 올리지 않은 **숨은 지식이 찾을 수 있는 상태**가 됨 |
| ② **필요한 사람을 찾아감** (일을 여는 쪽의 에이전트, 추천 에이전트) | 진행자가 목적(예: "업무 효율 아이디어 공모")만 말하면, 진행자의 에이전트가 자기소개를 검색하고 추천 에이전트가 맥락을 맞춰 후보를 골라 이유를 붙입니다. 심사·기록을 맡을 사람도 찾아 역할을 맡깁니다 | 공지·홍보 없이 **맞는 사람에게 직접 닿음**. 섭외 수작업이 사라짐 |
| ③ **응할지 근거로 판단** (내 에이전트) | 요청을 받으면 내 작업 영역(문장 인용), 내가 정한 규칙, 지금 상황, 위험, 상대의 신뢰(기록 확인)로 응하기·사람에게 묻기·넘김을 정하고 이유를 남깁니다 | 기회를 놓치지 않으면서 **맞지 않는 일은 걸러짐**. 사람은 필요할 때만 결정 |
| ④ **내 지식으로 결과물 작성** (내 에이전트) | 응하기로 하면 작업 영역 문서에서 맞는 아이디어를 골라 기획서로 다듬고 **출처 문서를 밝힙니다.** 문서에 없는 내용은 만들지 않고, 원문은 넘기지 않습니다 | 공모에 맞춰 **새로 쓰는 부담 없이** 참여 |
| ⑤ **진행과 평가** (진행자의 에이전트, 심사 에이전트) | 마감 뒤 진행자의 에이전트가 심사 요청과 채택 같은 다음 행동을 스스로 고르고, 심사 에이전트는 작성자를 모른 채 기준에 따라 점수와 의견을 냅니다 | 접수·전달·취합 **수작업이 사라지고**, 평가 근거가 남음 |

**AI와 코드의 분담**: 판단과 글쓰기는 AI가, 틀리면 안 되는 일(게시판 검색, 전자 서명, 먼저 등록한 사람 우선·계약 없는 심사 거절 같은 기록 규칙, 변조 탐지)은 코드가 합니다. AI가 판단을 잘못해도 누가 무엇을 냈고 무엇이 채택됐는지의 기록은 조작되지 않습니다.

**만들어지는 변화**: 지금은 사람과 사람이 공지와 메일로 연결되지만, 광장에서는 **사람의 에이전트끼리 직접 대화해(A2A) 연결·조율·기록을 끝내고** 사람에게는 결정할 일만 올라옵니다. 그래서 지식을 가진 사람은 쓰는 수고 없이 기회를 얻고, 지식이 필요한 사람은 찾아 헤매지 않고 맞는 사람에게 닿습니다.

### 문항 3

```text
3. 해커톤 2일 동안 구현해 보고 싶은 주요기능은 무엇인가요?
   아이디어가 구현되면 사용자가 무엇을 하고, 
   AI가 어떤 결과를 보여줄지 적어주세요.
```

**답변**

**사전 준비(완료)**: 전체 흐름이 끝까지 도는 프로토타입을 만들어 실제 LLM으로 실행했습니다(A2A 공식 SDK, 전자 서명, 해시 체인 기록). 시연에서 사람 자리는 직무·성격·경험이 다른 **LLM 페르소나 13명**이 맡고(에이전트의 LLM과 분리), 실제 도입에서는 사람이 그 자리에 들어옵니다. 마지막 실행에서 13명이 두 공간(응모 공간: 게시판 3곳, 심사 공간: 허가된 에이전트만 들어오는 게시판 1곳)에 나뉘어, 진행자 에이전트가 기록자 1명·심사자 2명과 역할 계약을 맺고, 아이디어 5건을 받아 두 심사자의 평균 점수로 2건을 채택했습니다. 기록 35건이 서명과 함께 남았고, 권한 없는 열람 거부와 기록 변조 탐지도 확인했습니다. 이 프로토타입은 공지를 올리는 방식이며, 해커톤에서 **찾아가 요청하는 방식**으로 바꿉니다. 발견·계약·서명·기록은 그대로 쓰고, 바뀌는 곳은 모집의 시작과 아이디어의 출처입니다.

**2일 동안 반드시 할 것**

1. **시연용 작업 영역 준비**: 응모자마다 아이디어가 쌓인 마크다운 문서 여러 개와 소유자 규칙, 현재 상황을 작성
2. **찾아가 요청하는 방식으로 전환**: 진행자 에이전트가 공지 없이 자기소개 검색과 추천 에이전트로 후보를 찾아 직접 요청하고, 각 에이전트가 작업 영역 문서에서 기획서를 다듬어 출처와 함께 제출
3. **Claude API 전환과 10회 반복 측정**: 자율 진행 완주율, 요청에 응한 비율, 기획서가 출처 문서에 근거한 비율, 심사 변별력(현재 개발용 LLM으로 12회 중 6회 완주)
4. **현장 참가자 2~3명**이 자기 작업 영역으로 실제 참여하고, 사람의 평가와 심사 에이전트의 점수를 비교
5. 대시보드 정리, 시연 리허설, 실패 대비 녹화

**시간이 남으면**: 기록자 여러 명이 서로 대조하는 구조, 확정 행동 전 사람 확인 단계, 기간이 정해진 권한, 기록된 실적을 자기소개에 싣기.

**시연 장면 (약 5분)**

1. 13명의 자기소개가 뜨고, 응모자마다 작업 영역 문서에 아이디어가 쌓여 있습니다. **게시판에는 공지가 없습니다.**
2. 진행자 에이전트가 검색으로 기록자 1명과 심사자 2명을 찾아 역할 계약을 맺습니다(양쪽 서명, 기록).
3. 진행자 에이전트가 자기소개 검색과 추천 에이전트로 후보를 찾아 **직접 요청**합니다.
4. 각 에이전트가 노트를 인용한 이유와 함께 응하기·묻기·넘김을 정하고, 응한 에이전트는 **출처 문서를 밝힌 기획서**를 보냅니다. 보내기 전에 먼저 등록하고, 받는 쪽은 수령 확인 서명을 돌려줍니다.
5. 마감을 누르면 진행자 에이전트가 스스로 심사를 맡기고 점수를 근거로 채택합니다.
6. 참여한 에이전트들의 자기소개가 경험을 반영해 새 버전으로 바뀝니다.
7. 열람 전용 에이전트의 대시보드에 구성원별 **강점과 실적**이 한 표로 드러나고, 기록을 몰래 고치면 잡아내며, 권한 없는 열람은 거부됩니다.

**사용자가 하는 일**: 진행자는 주제와 마감만 정하고, 구성원은 평소처럼 일하며 메모하고, 필요할 때만 확인합니다. **AI가 보여 주는 결과**: 인용이 달린 판단 이유, 출처가 달린 기획서, 심사 점수와 의견, 구성원별 강점·실적표.

**범위 밖(말로만 설명)**: 사내 로그인 연동, 포인트·인사평가 연계, 대규모 분산 합의.

### 문항 4

```text
4. 이 아이디어의 주요 사용자는 누구이며, 어떤 기대효과가 있나요?
   고객 가치 창출, 오류 감소, 정보 접근성 개선, 업무 효율 향상 등 
   기대하는 변화를 구체적으로 적어주세요.
```

**답변**

**주요 사용자** `[가정]`: 부서·회사·협력사 연합 같은 **커뮤니티**와 그 구성원. 시연은 삼성SDS 전사원 커뮤니티의 아이디어 공모입니다.

1. **일을 여는 사람**: 공모 진행자, 부서장, TF 리더, 협력사 연합 사무국. 공지·섭외·취합을 손으로 하던 사람입니다.
2. **응하는 구성원**: 경험과 아이디어는 있지만 기회를 놓치거나 나서지 않던 실무자. 쓰는 수고 없이 쌓아 둔 지식이 기회가 됩니다.
3. **역할을 맡는 구성원**: 심사·기록·추천에 능한 사람. 역할 수행이 실적으로 남습니다.

**기대효과 (사내에서 쓸 경우)**

| | 지금 | 에이전트 광장 |
|---|---|---|
| **능동적으로** | 공지를 기다리거나 사람이 직접 찾아 헤맴 | 필요한 쪽 에이전트가 맞는 사람을 찾아가고, 내 에이전트도 내게 맞는 기회를 먼저 찾음 |
| **제대로** | 제목만 보고 넘기거나 맞지 않는 일에 끌려감 | 내 작업 영역·규칙·상황을 근거로 맞는 것만 고르고, 이유를 남김 |
| **효율적으로** | 담당자가 섭외·홍보·접수·전달·집계를 수작업 | 연결·조율·기록을 에이전트가 하고, 사람은 결정이 필요할 때만 개입 |

- **숨은 실력자와 아이디어가 드러납니다.** 정리해 올리지 않은 지식도 작업 영역에 있으면 찾아오는 요청에 닿습니다. "공모를 몰라서" 놓치는 일이 크게 줄어듭니다.
- **공모 한 건의 진행이 가벼워집니다.** 심사자 섭외(검색과 계약), 홍보(직접 요청), 접수 확인(수령 서명), 심사 전달(작성자 정보 없이 일괄), 결과 집계(기록에서 자동 산출)를 에이전트가 처리합니다.
- **기여를 공정하게 평가할 근거가 생깁니다.** 낸 아이디어, 채택, 맡은 역할이 서명으로 공증되어, 평가와 보상을 인상이 아니라 기록에 근거해 할 수 있습니다. 회사 커뮤니티에서는 인사 프로필과 연결해 그대로 평가 근거가 됩니다.
- **새 시스템 투자 없이 시작합니다.** 게시판과 기록은 구성원의 에이전트가 나눠 맡으므로, 새 부서나 TF도 몇 명이 역할을 맡으면 바로 시작합니다. 드는 것은 각자 에이전트의 실행 비용입니다.
- **AI 비용도 필요한 곳에만 씁니다.** 검색으로 고른 후보에게만 요청이 가고, 관련 없는 요청은 검색기가 먼저 걸러 AI를 부르지 않습니다.

**측정 방법**: 근거 없는 수치는 제시하지 않습니다. 요청당 응한 비율, 공모 전에 이미 쌓여 있던 아이디어로 낸 비율, 부서 밖 응답자 비율, 에이전트의 판단과 본인 판단의 일치율, 진행자의 수작업 단계 수, 마감부터 채택까지 걸린 시간으로 잽니다. 해커톤 2일차에 반복 실행과 사람 참가로 첫 수치를 얻고, 도입 파일럿에서 기존 방식과 비교합니다.

### 문항 7

```text
7. 제안해 주신 아이디어에 대해 추가로 언급하고 싶은 내용이 있으면 
   작성해 주세요.
```

**답변**

1. **기존 도구와의 차이**: 사내 게시판·공모 시스템·사내 검색은 사람이 찾아가 읽고 판단해야 합니다. 에이전트 관리 체계(예: Microsoft Agent 365)나 에이전트 디렉터리 표준(예: AGNTCY, MIT NANDA)은 에이전트를 관리하거나 찾게 해 주는 데까지이고, 회사가 추론해 보여 주는 강점(예: Microsoft 365 People Skills)에는 실제로 해냈다는 증명이 없습니다. 에이전트 광장은 그 위에서 **에이전트가 찾아가 판단하고 참여하며, 커뮤니티가 스스로 운영하고, 지식과 실적이 개인 자산으로 공증되는** 다음 단계라 기존 도구와 함께 쓸 수 있습니다.
2. **왜 응하는가, 초기에는 어떻게 하나**: 응하는 쪽은 새로 쓰는 수고가 없고(이미 쌓인 지식), 채택과 역할 수행이 서명된 실적으로 남아 평가와 보상의 근거가 됩니다. 참여자가 적은 초기에는 진행자가 있는 일(공모, TF 모집)부터 부서 단위로 작게 시작하고, 게시판을 이어 넓힙니다.
3. **정보 보호와 신뢰 설계**
   - 작업 영역의 원문은 내 에이전트만 읽고, 다른 에이전트에게는 내 에이전트가 고른 결과만 건너갑니다. 게시판은 자기소개만 알고 아이디어를 보지 않습니다.
   - 성격이 다른 집단은 공간을 나눕니다. 심사자는 응모자와 분리된, 기간 있는 허가가 있어야 들어오는 공간에서 작성자를 모른 채 심사합니다.
   - 기록에는 내용 없이 해시·가명·서명만 남고 원문은 따로 두어 지울 수 있습니다. 기록 열람은 허가된 열람 전용 에이전트만 가능하고, 권한은 회수 절차 없이 기간이 지나면 끝납니다.
   - 실명·가명·익명은 커뮤니티가 정합니다. 회사는 서명 키를 인사 프로필과 연결하고(실명), 동호회 같은 좁은 커뮤니티는 선택하며, 익명 커뮤니티는 익명으로 씁니다. 시연은 회사 커뮤니티이며, 화면에는 심사 공정성을 위해 가명으로 표시합니다.
4. **확장**: 같은 구조에 역할만 바꾸면 전문가 상담, 부서 간 자료 공유, 협업 인원 모집이 됩니다. 새 기능은 누구나 앱으로 만들어 붙일 수 있습니다(예: 내 에이전트에게 "채팅방 열고 A, B 초대해"라고만 말하면 채팅 역할을 맡은 에이전트가 처리).
5. **알고 있는 한계와 대응**
   - 프로토타입은 공지 방식입니다. 찾아가 요청하는 방식은 2일 중 1~2순위로 바꿉니다.
   - 시연의 구성원은 LLM 페르소나라 참여율과 품질의 증거가 아닙니다. 현장 참가자의 실제 참여와 비교합니다.
   - 에이전트의 자율 진행은 실행마다 달라집니다(개발용 LLM 12회 중 6회 완주). Claude 전환 뒤 10회 반복 측정하고, 실패하면 정해 둔 순서로 대신 진행하며 그 사실을 실행 기록에 남깁니다.
   - LLM이 쓴 글은 과장이나 오류가 있을 수 있습니다. 인용과 출처를 코드로 대조하지만, 다듬는 과정에서 덧붙인 내용은 출처 문서와 대조하는 확인이 더 필요합니다.
   - 시연의 기록자는 1명입니다. 참여자가 기록마다 수령 확인 서명을 받아 보관하므로 누락을 증명할 수 있고, 기록자 여러 명의 대조는 해커톤 이후 과제입니다.
   - 다른 에이전트가 보낸 글 속에 숨긴 지시문에 대한 방어는 아직 없습니다. 서명과 기록 규칙은 코드로 강제되어 영향을 받지 않습니다.
   - 보상은 실적을 보여 주는 데까지이며, 포인트·인사평가 연계는 회사 정책 검토가 필요합니다.
