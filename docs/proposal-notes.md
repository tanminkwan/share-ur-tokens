# 신청서 작성 메모 (제출 대상 아님)

`hackathon-proposal.md`는 제출용이라 내부 판단과 미해결 과제는 여기에 둡니다.

## 사용자 확인이 필요한 가정

`review/premises.md`의 `[가정]` 항목 전부. 특히 다음이 신청서 방향을 좌우합니다.

1. 사내망에서 서버 간 직접 호출(p2p)이 허용되는가? 안 되면 문항 7-4의 후퇴 문구가 현실이 된다.
2. 사내 허용 LLM이 무엇인가? 임베딩 API도 되는가?
3. 해커톤이 사전 작성 코드를 제한하는가? `proto/` 아래 spike 두 개의 처리가 달라진다.
4. 데모 지식 도메인(현재 CI 캐시 설정 노하우)이 사내 청중에게 와닿는가?

## 예상 질문과 현재 답

| 질문 | 현재 답 | 신청서 위치 |
|---|---|---|
| 왜 블록체인(원장)이 필요한가, DB로 안 되나 | 수집가 2개가 서로 독립 검증하고 양쪽 서명을 요구하므로 운영자 한 명이 몰래 고칠 수 없다. 실제 체인이 아니라 해시 체인이며 이유는 변조 탐지와 이중 서명 증명이다 | 문항 1, 7-1·7-2 |
| 사내 위키·게시판과 무엇이 다른가 | 기여·출처가 서명으로 추적되고 조건을 협의한다 | 문항 1, system-overview 12절 |
| 원작자 보호가 실제로 되는가 | 선등록 증명까지만 된다. 남의 글을 먼저 올리면 막지 못한다. 이의 제기는 사람이 처리 | 문항 7-2 |
| 익명이면 책임은 누가 지는가 | 가명이며 감사·보안 담당이 사유를 남기고 재식별. 책임은 소유자 | 문항 7-3 |
| 보상이 어뷰징되지 않는가 | 서로 다른 소비자 수로 집계해 완화하나 완전 방지는 불가 | 문항 7-2 |
| 공급자는 왜 응하는가 | 기여가 가명별로 집계·가시화된다. 포인트·평가 연계는 범위 밖이라 유인의 크기는 미검증 | 문항 4, 7-5 |
| AI 없이 되는 것 아닌가 | 구조화·매칭·협상 해석에만 AI, 나머지는 코드. 켜기/끄기 비교로 시연 | 문항 2 |
| 사내 보안 정책을 통과하는가 | 사내 허용 LLM만 사용, p2p 허용 여부는 미확인 | 문항 6, 7-4 |
| 지식에 기밀·개인정보가 있으면? | 원문은 저장소에 두어 삭제 가능. 자동 탐지는 하지 않는다(MVP 범위 밖) | 문항 7-1 |

## 미해결 과제

- 사내 기존 도구(위키, 지식관리, Q&A)와 외부 유사 서비스 조사. 현재 차별점은 조사 없이 쓴 것이다.
- 지식 공유 문제의 실재 근거(인터뷰 3~5건 등)와 기대효과의 기준선.
- 공급자 유인의 크기: 기여 집계가 실제로 공유를 늘리는지.
- 지식 기밀 등급과 공개 범위 제어, 개인정보 탐지.
- 원장의 영속화와 수집가 간 A2A 통신 구현.
- 해커톤 주최 측의 실제 심사표 확인. 현재 기준은 공개 사례의 공통 경향이다.
