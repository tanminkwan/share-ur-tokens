# 신뢰와 보안

## 1. 신원: 가명

- peer의 식별자는 ed25519 공개키입니다. 모든 메시지와 원장 항목은 이 키로 서명합니다.
- 소유자와 공개키의 대응표는 **감사·보안 담당만** 접근하며, 접근마다 사유와 시각을 기록합니다. MVP는 파일 하나와 접근 로그로 대신하며 SSO 연동은 범위 밖입니다.
- 소유자는 서명 키로 자신이 작성자임을 소명할 수 있습니다. 이는 회사의 재식별과 별개의 경로입니다.
- 완전한 익명이라고 쓰지 않습니다. 회사는 재식별할 수 있고, 희소한 지식은 내용만으로 추정될 수 있습니다.

## 2. 원장의 신뢰 모델

[system-overview.md](system-overview.md) 4절의 보장·비보장 표를 따릅니다. 요약하면 원장은 **누가 언제 어떤 조건에 서명했는가**를 증명하고, 내용의 진위·품질·원작자의 실제 창작 여부는 증명하지 않습니다.

## 2-1. 절대자 peer (열람 권한)

원장을 읽을 수 있는 peer는 수집가의 허용 목록에 키가 있는 peer뿐이며, 요청은 서명과 60초 이내 시각을 요구하고 허용·거부가 모두 기록됩니다. 이 peer는 쓰기, 내용 열람, 재식별을 하지 못합니다. 다만 가명별 활동량과 공유 관계가 모두 보이므로 열람 키의 발급·회수·열람 사유 기록이 실제 도입에서 필요한 통제이며, MVP는 접근 기록만 남깁니다.

## 3. 위험과 대응

| 위험 | 설명 | MVP의 대응 | 남는 한계 |
|---|---|---|---|
| 남의 지식 선등록 | 타인의 내용을 먼저 올려 원작자로 기록 | 이의 제기 시 소명 절차(사람), `feedback` 신고 | 선등록자를 자동으로 가려내지 못한다 |
| 허위·저품질 지식 | 쓸모없는 지식을 올린다 | 거래 후 평가·신고, 기여는 서로 다른 소비자 수로 집계 | 진위를 자동 검증하지 못한다 |
| 기여 어뷰징 | 서로 가짜 거래로 기여를 올린다 | 서로 다른 소비자만 집계, 자기 소비 제외 | 다수의 가명을 만들어 우회할 수 있다 |
| 수집가 변조 | 한 수집가가 기록을 고친다 | 수집가 2개의 독립 기록과 `audit` | 둘이 공모하면 못 잡는다 |
| 사칭 | 다른 가명인 척한다 | 서명 확인 | 키 유출 시 무력 |
| 열람 권한 남용 | 열람 키 보유자가 가명별 활동을 추적한다 | 허용 목록, 접근 기록, 내용·실명 비노출 | 키를 누구에게 주는지가 정책이며 회수·사유 기록 미구현 |
| 프롬프트 주입 | 지식 텍스트에 에이전트 지시문을 섞는다 | 외부 텍스트를 지시가 아닌 데이터로만 취급, 정책은 코드가 평가 | 완전한 방어는 불가능하다 |
| 에이전트 오판 | 협상 중 부적절한 조건에 합의 | 정책 객체, 자동 확정 범위, 횟수 상한 | 해석 오류 자체 |

## 4. 사내 보안과 규정

- **데이터 반출**: LLM 호출은 사내 허용 서비스만 씁니다. 외부 LLM으로 사내 지식을 보내지 않습니다.
- **원문과 원장 분리**: 원문은 지식 저장소에만 두고 삭제할 수 있습니다. 원장은 해시, 가명, 서명만 담습니다.
- **공개 범위**: 지식에 공개 범위(전사, 부서, 지정 대상)를 달 수 있게 설계하되 MVP는 전사 공개만 구현합니다. 기밀 등급 분류와 개인정보 자동 탐지는 범위 밖이며, 입력 단계에서 경고 문구와 간단한 패턴 검사만 합니다.
- **p2p 연결**: 에이전트는 사내 서버에서 호스팅합니다. 서버 간 직접 호출 허용 여부는 미확인입니다. 허용되지 않으면 broker가 메시지를 중계하며 "거래는 peer 직접"이라는 분리는 성립하지 않습니다. 원장의 증명은 양쪽 서명 기반이라 이 후퇴와 무관합니다.
- **책임 소재**: 에이전트가 확정한 거래의 책임은 소유자에게 있고, 확정은 소유자가 취소할 수 있습니다. 양쪽 peer와 수집가가 기록을 남깁니다.
- **보상 연계**: 기여 집계는 가시화까지만 합니다. 포인트·인사평가 연계는 사내 정책과 법무 검토가 필요합니다.

법률·사내 규정의 최종 판단은 법무와 정보보안 부서의 확인이 필요합니다.
