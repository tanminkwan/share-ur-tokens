# 신뢰와 보안

무엇을 보장하고 무엇을 보장하지 않는지를 구현 기준으로 적습니다. "설계만 있음"과 "구현됨"을 구분합니다.

## 1. 신원: 가명

- peer의 식별자는 ed25519 공개키이고 화면에는 `가명-xxxxxx`로 보입니다. 모든 원장 항목과 자기소개는 이 키로 서명합니다.
- 상대 peer, 심사 peer, 절대자 peer에게 사람은 보이지 않습니다. 심사자는 작성자 가명조차 받지 않습니다.
- **실명 확인**: 설계는 "감사·보안 담당만, 사유를 남기고"입니다. **구현은 시연 수준**입니다. 대시보드의 실명 확인 버튼은 사유가 비어 있으면 거부하고 접근을 기록하지만, 누르는 사람이 감사 담당인지 확인하는 인증은 없습니다.
- 소유자는 서명 키로 자신이 작성자임을 소명할 수 있습니다(키를 가진 사람만 그 가명으로 서명할 수 있으므로). 회사의 실명 확인과는 별개의 경로입니다.
- **완전한 익명이 아닙니다.** 회사는 실명 확인할 수 있고, 자기소개의 직무·연차는 준식별자이며, 희소한 아이디어는 내용만으로 작성자가 추정될 수 있고, 직접 호출은 호출자 주소를 드러냅니다.

## 2. 원장의 신뢰 모델

원장에는 내용이 없습니다. 해시, 가명, 서명, 시각, 심사 점수만 있고 아이디어·심사 의견·채택 이유의 본문은 지식 저장소(해시 키)에 있어 삭제할 수 있습니다.

| 보장한다 (구현·실행 확인) | 보장하지 않는다 |
|---|---|
| 항목의 순서와 시각(역행 거절), 서명자 | 아이디어의 진위·품질 |
| 같은 내용 해시의 나중 `publish` 거절(먼저 등록). 응모자는 보내기 전에 기록 | 먼저 등록한 사람가 실제 창작자인가(남의 것을 먼저 올리면 그 가명이 먼저 등록한 사람. 소명은 사람이 처리) |
| `share`·`contract`의 양쪽 서명, nonce로 재전송 거절 | 두 수집가가 공모하는 변조 |
| `feedback`은 그 내용을 받은 가명만, `review`는 계약된 가명만 | 항목 삭제·끝 잘라내기(미검증) |
| 서명된 과거 항목을 고치면 감사(해시 재계산 + 서명 재검증)와 다른 수집가와의 대조로 탐지 | 여러 가명을 만들어 기여를 부풀리는 행위 |
| 내용을 지워도 증명 구조 유지 | 원장 영속성(현재 메모리. 재시작하면 사라짐) |

## 3. 열람 권한: 절대자 peer

- 원장을 읽을 수 있는 것은 수집가의 **허용 목록에 공개키가 있는 peer**뿐입니다. 열람 요청은 서명과 60초 이내 시각을 요구하고, 허용·거부 모두 기록됩니다(대시보드 '권한 없는 peer의 열람 시도' 버튼으로 거부를 시연).
- 절대자 peer는 쓰기, 내용 열람, 실명 확인을 못 합니다. 가져온 사본을 스스로 검증하고 두 수집가를 대조해 통계를 냅니다.
- **한계**: 가명별 활동량과 누가 누구와 주고받았는지가 모두 보이므로 이 키는 강력합니다. 키 발급·회수·열람 사유 기록은 구현하지 않았고, 절대자는 별도 A2A 노드가 아니라 데모 프로세스 안의 객체입니다. 대시보드 자체에도 인증이 없습니다.

## 4. 자기소개의 신뢰

자기소개는 peer의 비서가 작업 영역 노트를 요약해 쓴 글입니다. broker는 서명만 확인하고 **내용의 진위는 검증하지 못합니다.** "노트에 없는 경력은 만들지 말라"는 지시가 유일한 장치이며, 비서가 과장하거나 노트에 섞인 지시문에 영향을 받으면 그대로 게시됩니다. 사람이 게시 전에 검토·편집하는 기능은 설계상 가능하지만 시연용 구현에는 없습니다.

## 5. 위험과 대응

| 위험 | MVP의 대응 | 남는 한계 |
|---|---|---|
| 남의 아이디어 먼저 등록 | 응모자가 보내기 전 `publish`. 받는 쪽은 먼저 등록할 수 없음. 소명은 사람 | 아이디어를 **보기 전**에 가로채는 길은 막지만, 다른 경로로 알게 된 내용을 먼저 올리는 것은 못 막음 |
| 계약 없는 심사·사후 심사 조작 | `review`는 계약된 가명만, 점수는 서명된 페이로드에 포함 | 계약된 심사자 본인의 편향 |
| 기여 부풀리기 | 서로 다른 소비자 수로 집계, 자기 소비 제외 | 다수 가명 |
| 수집가 변조 | 수집가 2개 독립 기록, 감사, 절대자 대조 | 둘의 공모, 삭제·절단 |
| 사칭 | 서명 확인 | 키 유출 |
| 열람 권한 남용 | 허용 목록, 접근 기록, 내용·실명 비노출 | 키 회수·사유 기록 미구현 |
| 허위 자기소개 | 서명(누가 썼는지만), 프롬프트 지시 | 진위 검증 없음 |
| 프롬프트 주입(아이디어·자기소개·노트에 지시문) | **미구현.** 서명·원장 규칙 같은 코드 강제 부분만 영향을 받지 않음 | 비서 판단, 매칭, 심사, 자기 요약 모두 영향받을 수 있음 |
| 에이전트 오판(잘못된 채택, 중복 요청) | 각 도구의 원장 규칙, 단계 상한(12), 실패 시 고정 순서 | 판단 자체. 같은 입력에서도 결과가 달라질 수 있음 |

## 6. 운영상의 원칙

> 사내망 보안(망 정책, 사내 허용 서비스, 정보보안·법무 승인)은 사용자 결정으로 이 기획의 범위 밖입니다.

- **LLM 키**: Claude API 또는 OpenAI 호환 엔드포인트를 환경변수로 선택하며, 키는 저장소 밖(`.env`)에만 둡니다.
- **내용과 원장 분리**: 본문은 지식 저장소에만 두어 삭제할 수 있습니다.
- **배치**: A2A에는 중앙 서버가 없습니다. 각 peer가 접속 창구를 열고 서로 직접 호출하며, 받는 쪽에 들어오는 연결이 가능해야 합니다.
- **책임**: 에이전트가 한 응모·역할 계약·심사·채택의 책임은 peer의 소유자에게 있습니다. 소유자가 확정을 취소하는 경로는 구현하지 않았습니다.
- **보상 연계**: 기여 집계의 가시화까지만 합니다.
