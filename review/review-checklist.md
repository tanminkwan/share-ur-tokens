## 3. 기술적 주장의 오류와 자기모순

| ID | 리뷰 포인트 | 상태 | 반영 내용 요약 | 커밋 |
|---|---|:-:|---|---|
| R3-1 | 기업·금융권 PII 보호를 내세우지만 공급자 PC에 프롬프트가 노출되고, 정규식 마스킹의 한계가 있음 | ⬜ | | |
| R3-2 | Context Sharding이 프라이버시를 강화한다는 주장은 반대임. Peer마다 대화 전체가 노출됨 | ✅ | 추적 차단 주장을 삭제하고, "Peer를 자주 바꿀수록 대화 전체를 보는 상대가 늘어난다"는 주의사항으로 바꿈. Sticky 라우팅으로 노출 범위를 줄이는 원칙을 추가 (`dynamic-peer-switching.md` §4-③, `hackathon-proposal.md` 4번, `system-overview.md` §1.2) | `26d2c33` |
| R3-3 | 익명성 주장과 소비자 DID 서명 요구가 충돌함 | ⬜ | | |
| R3-4 | 멱등성 덕분에 0.5초 무중단 복구가 된다는 주장이 틀림. 재전송 시 이중 과금 문제가 생기고, Peer를 바꾸면 캐시가 깨져 비용이 늘어남 | ✅ | 같은 세션은 같은 Peer로 보내는 Sticky 라우팅을 기본으로 하고, 장애 시 로컬 기록으로 다시 계산하는 Fallback 방식을 도입. 멱등성/500ms/100% 무중단 주장을 삭제하고, 스트리밍 도중 이탈 시 재요청·부분 과금·이중 과금 방지가 필요하다고 명시. 영수증에 캐시 적중/미적중 토큰을 구분해 기록하도록 함. Peer 측 KV 캐시(`past_key_values`) 관리·전달안을 검토했으나 채택하지 않은 근거를 정리 (`dynamic-peer-switching.md` §2·§4·§5·§6, `hackathon-proposal.md` 1번·7-4번, `system-overview.md` §1.2, `p2p-and-identity.md`) | `26d2c33` |
| R3-5 | 스마트 컨트랙트가 OpenAI 에러를 검증할 수 없음(서명 없음, 오프체인 데이터, 증거 위조 가능) | ⬜ | | |
| R3-6 | 모델 바꿔치기(공급자가 더 싼 모델로 응답)를 검증할 방법이 없는데 다루지 않음 | ⬜ | | |
| R3-7 | "100%", "완벽", "원천 차단", "세계 최초" 같은 과장 표현과 오래된 모델명(GPT-4o, Claude 3.5) | 🟡 | 피어 스위칭과 관련된 부분(`hackathon-proposal.md` 1번·7-4번, `system-overview.md` §1.2, `dynamic-peer-switching.md`)에서 과장 표현을 삭제함 (`26d2c33`). 오래된 모델명(GPT-4o, Claude 3.5 Sonnet, Llama-3)은 특정 세대에 묶이지 않는 표현(제공사명, 오픈 가중치 계열)으로 바꾸고, 예시 모델 ID는 `claude-sonnet-5-5`로 갱신. 가격 예시는 "가상의 모델 + 공식 가격표 Oracle 연동"으로 바꾸고, 근거 없는 "수백 GB" 모델 크기 주장을 삭제 (`system-overview.md`, `privacy-and-tool-calling.md`, `pricing-mechanism.md`, `feasibility-and-tos-strategy.md`). 다른 문서의 "100%/완벽/세계 최초" 표현은 남아 있음 | `26d2c33`, (R1-1과 같은 커밋) |
