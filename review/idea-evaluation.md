## 1. 치명적 결함: 핵심 전제가 사실과 다름

**① 구독제에는 팔 수 있는 "남는 토큰"이 없음**
- ChatGPT Plus와 Claude Pro는 웹/앱 사용 권한일 뿐, API 키를 주지 않는다. 이걸 P2P로 팔려면 세션 토큰을 탈취하거나 웹 UI를 스크래핑해야 하고, 이는 명백한 약관 위반이자 계정 공유다.
- 문서는 "구독 잔여 토큰"과 "API 키"를 계속 섞어 쓰고 있다. 둘은 완전히 다른 상품이다.

**② API는 쓴 만큼 내는 구조라 "버려지는 잔여분"이 거의 없음**
- API 요금은 사용량 과금 또는 선불 크레딧이다. 매달 소멸하는 구조가 아니다.
- 따라서 `pricing-mechanism.md`의 만료 감가 계수 Ψ(Δt)("만료 24시간 전 덤핑")는 존재하지 않는 상황을 모델링한 것이다.
- 더 큰 문제는 공급자 입장에서 $1어치 API 호출을 $0.70에 팔면 30% 손해라는 점이다. 공급자가 참여할 경제적 이유가 없다. 플랫폼 경제의 엔진이 성립하지 않는다.

## 2. 법률·약관: 해커톤 심사에서 바로 걸릴 부분

- 문서 제목부터 "ToS 회피 전략", "단속 무력화", "탐지 불가능"이다. 여기에 이상 트래픽 탐지를 피하려는 "인간 모방 Jitter"까지 설계되어 있다(`feasibility-and-tos-strategy.md` §3). 이건 사실상 **"빅테크의 어뷰징 탐지를 우회하는 방법"** 문서로 읽힌다.
- "Safe Harbor로 완벽 면책"이라는 주장은 법적으로 틀렸다. 침해를 목적으로 설계하고 홍보한 P2P 소프트웨어는 유도책임을 진다(MGM v. Grokster 판례). 지금 문서 자체가 그 고의를 입증하는 증거가 된다.
- 은행 에스크로와 DEX 상장 `$SUT` 토큰을 결합하는 구상은 국내에서 특금법, 가상자산이용자보호법, 금융위 인가 문제로 은행이 참여할 수 없는 구조다. 그런데 이걸 "완벽한 시너지"라고 쓰고 있다.
- 회사 내부 해커톤이라면, **고객사이자 파트너인 OpenAI·Anthropic의 약관을 우회하는 제품**은 기술적 완성도와 상관없이 회사가 채택할 수 없는 주제다.

## 3. 기술적 주장의 오류와 자기모순

| 문서의 주장 | 실제 |
|---|---|
| 기업·금융권 PII 보호 및 망분리 준수 | 같은 문서(`system-overview.md` §4.2)가 "공급자 PC에 프롬프트 노출"을 인정함. 정규식 마스킹은 이메일·키 정도만 잡고, 코드와 문맥 속 기밀은 못 잡음 |
| Context Sharding으로 프라이버시 강화 | 턴마다 **대화 전체 히스토리**를 새 공급자에게 보냄. 오히려 노출되는 상대가 N명으로 늘어남 |
| 빅테크 추적 차단(익명) | 분쟁 해결을 위해 모든 프롬프트에 소비자 DID 서명을 붙이게 함. 익명성과 정면으로 충돌 |
| 멱등성 덕분에 0.5초 무중단 복구 | LLM 호출은 비용 면에서 멱등하지 않음. 재전송하면 이중 과금 분쟁이 생기고, 피어를 바꿀 때마다 프롬프트 캐시가 깨져 비용이 오름 |
| 스마트 컨트랙트가 OpenAI 에러를 검증해 자동 배상 | OpenAI 응답에는 서명이 없음. 컨트랙트는 오프체인 HTTPS 응답을 검증할 수 없음(zkTLS 같은 기술이 필요). 계정 정지는 동기식 400 응답으로 오지도 않음. 공급자가 증거를 위조할 수 있음 |
| (언급 없음) | **모델 바꿔치기**: 공급자가 gpt-4o 대신 mini 모델로 답해도 소비자가 검증할 방법이 없음. 이것이 이 시장의 핵심 신뢰 문제인데 다루지 않음 |
| 각종 "100%", "완벽", "원천 차단", "세계 최초" | 기술 심사위원에게는 신뢰도를 깎는 표현. 모델명(GPT-4o, Claude 3.5)도 오래됨 |

## 4. 독창성

- 중앙화 API 중계(One-API, OpenRouter, 중국의 "API 중계" 회색시장), 구독 공유 서비스(구독 파티 계열), 탈중앙 추론(Bittensor, Morpheus)이 이미 있다. SUT는 이들을 합친 것이다.
- 진짜로 새로운 요소는 "가정용 IP로 상용 API를 탐지 없이 재판매"하는 것뿐인데, 이건 장점이 아니라 리스크다.
- "세계 최초"라는 주장은 검증되지 않았다. 비슷한 회색시장이 이미 크게 존재한다.

## 5. 해커톤 적합성

**긍정적인 점**
- 2일 MVP 범위(로컬 OpenAI 호환 프록시, WebSocket 릴레이, 정규식 마스킹, 토큰 카운트 영수증)는 현실적이다. 오히려 작은 편이다. LiteLLM을 쓰면 하루면 된다.
- Cursor에서 Base URL만 바꿔 바로 동작하는 데모는 직관적이다.

**부정적인 점**
- 데모 자체가 "내 API 키를 남이 쓰게 하는" 장면이다. 무대 위에서 약관 위반을 시연하는 셈이다.
- 기술적으로 어려운 부분(신뢰 검증, 정산, 분쟁 처리)은 전부 MVP 범위 밖이다. 그래서 데모는 "프록시 두 개를 연결한 것"으로 보여 기술 깊이 점수가 낮게 나올 수 있다.
- AI 활용 항목의 "에이전트들이 스펙을 자율 협상하여 무결점 완성"은 과장으로 보인다.

## 6. 권고: 살릴 수 있는 방향

이 문서에서 실제로 가치 있는 부분은 **로컬 OpenAI 호환 게이트웨이, PII 마스킹, 쿼터 재배분, 턴 단위 라우팅**이다. 이것들을 합법적인 맥락으로 옮기면 경쟁력이 생긴다.

1. **사내(기업) LLM 쿼터 풀링 게이트웨이 (추천)**
   - 한 기업이 맺은 계약 안에서 부서별 할당량과 유휴 쿼터를 재배분한다.
   - PII 마스킹, 감사 로그, 부서별 과금(chargeback)을 붙인다.
   - 문서의 금융권 시나리오가 그대로 살아나고, 약관 문제가 없으며, 회사 사업과도 맞는다.
2. **로컬·오픈 모델 GPU P2P 공유**
   - 약관 리스크가 없다. 다만 기존 프로젝트와 겹쳐 차별점이 필요하다.
3. **멀티 프로바이더 라우터 + 프라이버시 계층**
   - 턴 단위 라우팅 아이디어를 "여러 공식 계정과 모델 사이의 비용·품질 최적 라우팅"으로 바꾼다.

어느 방향이든 문서에서 "ToS 회피", "탐지 불가", "`$SUT` 토큰/DEX", "은행 에스크로", "100%/세계 최초" 표현은 빼는 것을 강하게 권한다.
