# 프로젝트 전제

> 리뷰어가 문서 간 일관성을 검사하는 기준입니다. 전제도 비판 대상입니다.
> `[확정]`은 사용자가 직접 정한 것, `[가정]`은 문서 작성을 위해 임시로 둔 값입니다. `[가정]`은 사용자가 확인하면 `[확정]`으로 바꿉니다.
> 갱신일: 2026-10-28

## 확정

- `[확정]` p2p 구조를 유지한다. LLM 중계(토큰 공유) 아이디어는 폐기했다.
- `[확정]` peer는 정보·지식을 **제공하거나 소비**하는 주체다. peer 간 통신은 p2p + a2a다.
- `[확정]` broker는 제공자가 노출한 정보를 맥락 기반으로 domain별 DB로 만들고, 요청에 답변지를 만든다. broker들은 서로 소통한다. **broker는 본래 기능(발견)만 한다.**
- `[확정]` 거래·공유 내용의 기록은 broker가 아니라 **별도 역할(기록자, recorder)**이 한다. 기록자는 원장 방식으로 기록하며, 원장의 역할은 peer 간 거래·공유를 **증명**하는 것이다. 용도는 원작자 보호, 지식 추적, 보상·패널티의 근거다.
- `[확정]` 사내 익명성(가명)을 보호하면서, 실제 거래·공유된 정보(아이디어, 지식)는 사내 자산으로 흡수한다. 이것이 이 아이디어의 강점이다.
- `[확정]` 대회는 대기업 사내 임직원 대상 2일 AI 해커톤이다. 신청서 7개 문항은 주최 측 양식이며 유지한다. 심사 기준은 이전과 같은 축에 공개 사례의 공통 항목을 더했다(`references/criteria.md`).
- `[확정]` 아래 [합의 추천값]은 사용자가 "그대로 진행"으로 승인했다.

## 합의 추천값 (사용자 승인)

- 원장은 해시 체인 + 참여자 서명 + 기록자 서명으로 구현한다. 시연은 기록자 1명이며 복수 기록자는 해커톤 이후다. 실제 허가형 블록체인은 확장 경로로만 언급한다.
- 실명 확인은 사내 감사·보안 담당만 하며 사유와 시각을 기록한다.
- 보상은 **기여 집계와 가시화**까지만 한다. 사내 포인트, 금전, 인사평가 연계는 범위 밖이다.

## 시연 방향 (사용자 확정, 2026-10-28)

- `[확정]` LLM은 해커톤에서 제공하는 **Claude API 키**를 쓴다. 사전 작성 코드 제한 여부는 고려하지 않는다. 삼성SDS클라우드 Simple AI Inference(OpenAI 호환, `gpt-oss-120b`)는 **Claude 키가 없는 동안 개발·검증용으로만 임시 사용**한다. 신청서의 계획 LLM은 Claude API다(사용자 지시 2026-10-28). 키는 저장소 밖(`.env`, git 무시)에만 둔다.
- `[확정]` **지금 우선순위는 구현이 아니라 `docs/hackathon-proposal.md`(제출용 신청서)다.** 구현은 시연 근거를 확인하는 수준으로만 한다.
- `[확정]` 시연의 peer는 각자 개성 있는 **페르소나**를 가진 약 10명이며, 사람의 역할을 한다. peer 에이전트(비서)에 붙는 LLM과 별개로, **진짜 사람 역할을 하는 LLM**을 둔다.
- `[확정]` 시연 흐름: 요청자(나, 이벤트 진행자)의 peer가 **아이디어 공모**를 올린다 → 각 peer 에이전트가 자기 페르소나에게 공모 내용을 전달한다 → 페르소나가 아이디어를 만들어 peer 에이전트를 통해 **p2p + a2a로 요청자에게** 준다. 아이디어를 줄 때 peer 간 connection이 생긴다.
- `[확정]` peer 중에 **심사에 능한 peer**가 있다. **만남의 순서(사용자 확정 2026-10-28)**: 심사자 peer가 자신의 역할을 꽤 긴 기간 공개(broker에서 검색 가능) → 이벤트 peer가 이벤트에 필요한 심사자를 찾다가 발견해 서로 contact → 역할을 부여하는 **계약(원장)** → 이후 이벤트 peer가 이벤트(공모)를 올리고 응모자 peer들이 이벤트를 받는다.
- `[확정]` 이 모든 흐름은 코드가 아니라 **AI agent 간 통신**으로 유연하게 흐른다.
- `[확정]` **작업 영역과 자기소개(사용자 확정 2026-10-28)**: 각 peer는 자기 working 영역에 지식과 경험이 축적되고, peer agent가 이를 요약해 자신의 역할과 정체를 broker에 게시한다. 예: 심사자 peer가 아이디어 심사에 관한 지식과 원칙을 만들면 그것이 게시되고, 이벤트 peer 같은 수요자가 컨택한다. 자기 요약은 자동(peer agent가 알아서 갱신)도 가능하고 사람이 편집할 수도 있지만, **시연에서는 자율성을 강조하기 위해 자동**으로 만든다.
- `[확정]` **이름(사용자 확정 2026-10-28)**: **에이전트 광장 (Agent Agora)**. 사내·아이디어로 범위를 좁히지 않는다. AI 에이전트가 유연하게 자율적으로 무엇이든 하고, peer의 역할 조합에 따라 여러 비즈니스 모델과 소통 방식이 생긴다. 사내 아이디어 공모는 시연 예시다.
- `[확정]` **역할 모델(사용자 확정 2026-10-28)**: 구성원은 peer 한 종류다. broker(발견)와 recorder(기록)도 peer가 자발적으로 공개해 맡는 인프라 역할이며, 역할 수행은 보상(기여 집계)의 근거가 된다. 요청자·응모자·심사자는 공모별 역할 계약으로 맡는 이벤트 역할이다. recorder는 broker를 통해 발견하고 p2p로 접속한다.
- `[확정]` **broker는 기계적으로 일한다(사용자 확정 2026-10-28)**: AI 에이전트가 없다. 프로필과 공지(만기 있음)를 게시하고, 공지의 응모 대상(예: `소속: 삼성SDS`)과 프로필 라벨이 맞는 peer 전원에게 그 공지를 보여 준다. 맥락 검색은 BM25나 임베딩 같은 검색기가 한다. AI가 필요한 매칭은 **추천 peer** 역할이 broker의 검색기를 써서 자기 AI로 공지와 프로필을 맞춰 본다.
- `[확정]` **핵심 메시지(사용자 확정 2026-10-28)**: 필요하거나 선호하는 정보에 대한 접근과 참여를 **더 능동적으로, 더 제대로, 더 효율적으로** 할 수 있다는 것. 사내에서 쓸 경우 정보 접근성 개선과 업무 효율 향상을 강조하고, 개인 에이전트가 사내 자원을 혼자 찾아 헤매는 것보다 a2a가 효율적이라는 점을 근거로 든다.
- `[확정]` **시연을 아이디어 공모로 고른 이유(사용자 2026-10-28)**: 대부분은 아이디어가 있어도 응모 여부를 모르거나 접근이 어려워 주저한다. 에이전트가 먼저 찾아오고, 응모할 만한지 판단하고, 대신 제출해 이 주저함을 줄이는 것이 핵심 메시지를 가장 잘 보여 준다. 실태 수치는 없다.
- `[확정]` **나의 자산(사용자 2026-10-28)**: peer(또는 사람)는 자신의 강점·노하우·지식을 계속 축적할 수 있고, 그것은 자신의 자산이 되며, 이 생태계에서 더 잘 드러날 가능성이 높아진다는 것도 장점이다. 그 자산은 **작업 영역에 축적된 지식**과 **원장에 드러난 실적**이다.
- `[확정]` **커뮤니티 단위(사용자 확정 2026-10-28)**: 부서·회사 등 커뮤니티 단위로 쓸 때 가장 강력하다. 커뮤니티의 경계는 라벨, 게시판·기록은 구성원 peer가 맡으므로 **중앙 서버 자원이나 유지보수 공수가 필요 없다**.
- `[확정]` **broker 3곳(사용자 확정 2026-10-28)**: 탈중앙화된 모습을 보이기 위해 broker를 3개 쓴다. peer 3~4명이 각 broker에 기본(primary)으로 붙고, 공지가 생기면 broker 사이에 공유된다.
- `[확정]` **응모는 각 peer가 스스로 정한다**: 근거는 ① 작업 노트의 적합성(인용) ② 소유자 규칙 ③ 이득과 여력 ④ 위험 ⑤ 원장으로 확인한 상대 신뢰. 결과는 응모·사원에게 묻기·넘김.
- `[확정]` **원장은 분산·탈중앙 설계**다. 시연은 recorder 1명(응모자 peer 중 하나, 보안·컴플라이언스 담당)이며, 복수 recorder의 일관성 알고리즘은 공개된 기술이므로 해커톤 이후에 한다. recorder는 자신이 기록하는 공모에 응모하지 않는다.
- `[확정]` **사내망 보안은 고려하지 않는다(사용자 지시 2026-10-28)**: 망 정책, 사내 허용 서비스, 정보보안·법무 승인은 이 기획의 범위 밖이다. 신청서와 리뷰에서 다루지 않는다.
- `[확정]` **용어**: 생소한 단어 대신 자연스러운 말을 쓴다(역할 계약, 먼저 등록, 기록자 서명, 실명 확인 등).
- `[확정]` **절대자 peer**: 원장을 마음대로 볼 수 있는 peer를 하나 둔다. 예로 대시보드는 이 peer를 통해 원장 내용을 보고 통계를 낸다. 읽기 전용이며 내용과 실명은 보지 못한다.
- `[확정]` 시연에 나타난 peer들과 그 역할은 **고정된 것이 아니라 이 아이디어 생태계의 한 예**다. 시스템에 직책별 노드를 두지 않는다.

## 가정 (사용자 확인 필요)

- `[가정]` 사용자는 해당 기업의 임직원이고, peer는 임직원 또는 부서의 AI 에이전트다. 에이전트는 사내 서버에서 호스팅한다.
- `[가정]` 공모 주제의 예는 "신입 사원 첫 달 적응 아이디어"다. 최종 시연 주제는 미정.
- `[가정]` 해커톤 환경에서 localhost 포트 사용과 Claude API 동시 호출(약 15회)이 가능하다.
- `[가정]` 신뢰·평판 체계(기여 집계 이상)는 MVP 범위 밖이다.

## 용어

| 용어 | 정의 |
|---|---|
| peer | 지식을 제공하거나 소비하는 에이전트 단위. 한 peer가 두 역할을 겸할 수 있다 |
| 가명 | peer의 ed25519 공개키. 소유자와의 대응은 감사·보안 담당만 안다 |
| 제공자 peer / 소비자 peer | 지식을 발행·제공하는 peer / 요청하고 받는 peer |
| 노출(advertise) | 제공자가 "무엇을 줄 수 있는지"의 요약과 조건을 broker에 알리는 일 |
| broker | 노출을 맥락 기반으로 정리한 domain별 DB를 가지고 요청에 답변지를 만드는 노드. 거래 내용을 보지 않는다 |
| 답변지 | 요청에 대한 broker의 응답. 후보 요약과 공급자 peer 접속 정보를 담는다 |
| p2p 연결 | 소비자가 답변지의 주소로 공급자 peer의 A2A 엔드포인트를 broker 없이 직접 호출하는 것. 발견까지 탈중앙이라는 뜻은 아니다 |
| a2a 거래 | 연결된 두 에이전트가 이용 조건을 협의하고 지식을 전달하는 일 |
| 기록자(recorder) | 기록 역할을 공개한 peer. 원장 항목을 검증하고 기록자 서명을 남겨 보관한다. 시연은 1명 |
| 원장 | 해시 체인으로 이어진 append-only 기록. 내용이 아니라 해시, 가명, 서명을 담는다 |
| 지식 저장소 | 발행된 내용(아이디어 등)의 사본을 해시 키로 두는 곳. 삭제할 수 있다 |
| 절대자 peer | 기록자의 열람 허용 목록에 키가 있는 읽기 전용 peer. 원장을 가져와 검증하고 통계를 낸다 |
| 작업 영역 | peer가 지식·경험 노트를 쌓는 곳. 비서가 이를 요약해 자기소개로 게시한다 |
| 계약(contract) | 이벤트 peer가 다른 peer에게 이벤트 한정 역할(예: 심사자)을 맡기는 양쪽 서명 원장 항목 |
| 비서 에이전트 | peer 안에서 요청을 받아 사원에게 전달할지 판단하고 사원을 대신해 통신하는 LLM 역할 |
| 페르소나 | 시연에서 사람을 대신해 아이디어를 내거나 심사하는 별도의 LLM 역할. 개성 있는 프로필을 가진다 |
| 공모 | 요청자가 올리는 아이디어 모집 요청 |
| 발행(publish) / 공유(share) / 피드백(feedback) / 계약(contract) | 먼저 등록 / 두 peer가 양쪽 서명으로 넘김 / 심사·채택 / 역할 계약 |
| 기여 | 내 내용을 받은 서로 다른 사람의 수, 채택 수, 맡은 역할 수 |
