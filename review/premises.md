# 프로젝트 전제

> 리뷰어가 문서 간 일관성을 검사하는 기준입니다. 전제도 비판 대상입니다.
> `[확정]`은 사용자가 직접 정한 것, `[가정]`은 문서 작성을 위해 임시로 둔 값입니다. `[가정]`은 사용자가 확인하면 `[확정]`으로 바꿉니다.
> 갱신일: 2026-10-28

## 확정

- `[확정]` p2p 구조를 유지한다. LLM 중계(토큰 공유) 아이디어는 폐기했다.
- `[확정]` peer는 정보(상품 판매, 이벤트 정보, 특정 분야 지식 등)를 **제공하거나 소비**하는 주체다.
- `[확정]` peer 간 통신은 p2p + a2a다.
- `[확정]` broker는 제공자 peer가 노출한 정보를 맥락 기반으로 domain별 DB로 만든다. broker들은 서로 소통한다.
- `[확정]` 흐름: 제공자 노출 → broker DB화 → 소비자 요청 공개(검색) → broker가 자기 DB 또는 다른 broker를 조회해 답변지(공급자 peer 정보 포함) 전달 → 소비자가 p2p 연결 → a2a로 거래·교환 자동 수행.
- `[확정]` 대회는 대기업 사내 임직원 대상 2일 AI 해커톤이다. 심사 기준은 이전과 같은 축에 공개 사례의 공통 항목을 더했다(`references/criteria.md`).

## 가정 (사용자 확인 필요)

- `[가정]` 사용자는 해당 기업의 임직원이고, peer는 임직원 또는 부서의 AI 에이전트다.
- `[가정]` 데모 도메인은 사내 정보 교환이다(예: 사내 세미나·이벤트 안내, 부서별 노하우, 중고 물품 교환). 최종 도메인은 미정.
- `[가정]` 거래·교환의 대가는 실제 금전이 아니다. 정보와 정보의 교환, 또는 무상 제공(예: 사내 포인트 없이 약속·예약)을 기본으로 한다.
- `[가정]` MVP는 사내 네트워크 안의 프로세스(에이전트 3~5개, broker 2개)로 구성한다. 구현은 A2A 1.0 + `a2a-sdk`(Python 3.11) + SQLite이고, LLM은 OpenAI 호환 어댑터로 사내 허용 LLM을 가리킨다. LLM이 없으면 규칙·TF-IDF 폴백으로 동작한다(`docs/system-overview.md`).
- `[가정]` 신뢰·평판 체계는 MVP 범위 밖이며 문서에는 한계로 명시한다.

## 용어

| 용어 | 정의 |
|---|---|
| peer | 정보를 제공하거나 소비하는 에이전트 단위. 한 peer가 두 역할을 겸할 수 있다 |
| 제공자 peer | 자신의 정보를 broker에 노출하는 peer |
| 소비자 peer | 자신의 요청을 공개하고 답변을 받는 peer |
| 노출(advertise) | 제공자가 "무엇을 줄 수 있는지"를 broker에 알리는 일 |
| broker | 노출된 정보를 맥락 기반으로 색인한 domain별 DB를 가지고, 요청에 답변지를 만드는 노드 |
| 답변지 | 요청에 대한 broker의 응답. 후보 정보와 공급자 peer 접속 정보를 담는다 |
| p2p 연결 | 소비자가 답변지의 주소로 공급자 peer의 A2A 엔드포인트를 broker 없이 직접 호출하는 것. 발견까지 탈중앙이라는 뜻은 아니다 |
| a2a 거래 | 연결된 두 에이전트가 사람의 개입 없이 조건을 협의하고 거래·교환을 수행하는 일 |
